# Copy As Implementation Plan

> **For Codex:** Execute this plan with `superpowers:executing-plans` and
> `superpowers:test-driven-development`. Add each behavior test first, confirm
> the focused test fails for the expected reason, then write the smallest
> implementation that passes it.

**Goal:** Let a user copy either the existing locator hash or a configurable,
compact source context while preserving one validated registration pipeline and
the existing locator/MCP behavior.

**Architecture:** Upgrade the shared global settings contract to schema v4,
extend the authenticated development registration response with its already
validated canonical file path, and keep clipboard formatting in a pure client
module. The settings popover writes complete v4 snapshots; the click handler
always registers first, then delegates the exact clipboard payload to the pure
formatter.

**Tech Stack:** TypeScript, Astro integration middleware, browser Shadow DOM,
Vitest, Playwright.

## Constraints

- Preserve all existing uncommitted color and parent-level work.
- Do not change hit resolution, hover target selection, hashes, manifest
  structure, MCP response, click cancellation, pseudo-element handling,
  `pointer-events:none` handling, overlay label placement, or FAB styling.
- Keep the popover width and existing Trigger/Preferences UI unchanged; insert
  Copy As between those sections.
- Do not persist disclosure state or expose absolute source paths in the DOM,
  manifest, MCP, boot config, or settings.
- The repository is already dirty on `main`; use test checkpoints rather than
  commits unless the user separately authorizes commits.
